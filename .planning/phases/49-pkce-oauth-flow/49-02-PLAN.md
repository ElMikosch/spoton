    Extend Settings.pm to handle the PKCE OAuth flow for AUTH-01. Three new HTTP endpoints
    plus modifications to new() and handler().

    In new(): Register three new addRawFunction endpoints following the existing
    discoveryStatus/start/stop pattern:
    - 'plugins/SpotOn/settings/pkce/start' => _pkceStartHandler
    - 'plugins/SpotOn/settings/pkce/callback' => _pkceCallbackHandler
    - 'plugins/SpotOn/settings/pkce/manual' => _pkceManualHandler

    In handler(): After the existing degradedMode assignment, add a new template variable:
    $paramRef->{pkceConfigured} — set to 1 if any account has a pkce_tokens.json file
    in its cache directory (iterate getAccountIds, check file existence via
    PKCE::loadTokens($id)). This tells the template whether PKCE auth has been used.

    Sub _pkceStartHandler($httpClient, $response):
    - CSRF check via _csrfCheck (same as discovery handlers)
    - Require Plugins::SpotOn::API::PKCE
    - Determine client_id: use $prefs->get('clientId') if set, otherwise
      require Plugins::SpotOn::API::Client and use SPOTON_DEFAULT_CLIENT_ID
    - Generate code_verifier via PKCE::generateCodeVerifier()
    - Generate code_challenge via PKCE::generateCodeChallenge($verifier)
    - Generate nonce: 16 random hex bytes via sprintf('%08x%08x', rand(2**32), rand(2**32))
      (LMS has no direct /dev/urandom helper but this is sufficient for CSRF state — the
      real security is in the code_verifier)
    - Build the LMS callback URL: determine LMS base URL from the HTTP request object.
      Use $response->request->header('Host') to get the host:port, prepend 'http://',
      append '/plugins/SpotOn/settings/pkce/callback'. This ensures the callback points
      to the same LMS instance the user is currently on.
    - Build state via PKCE::buildState($callbackUrl, $nonce)
    - Store verifier via PKCE::storeVerifier($nonce, $verifier)
    - Build auth URL via PKCE::buildAuthorizationUrl($clientId, $codeChallenge, $state)
    - Respond with JSON: { url => $authUrl, nonce => $nonce }

    Sub _pkceCallbackHandler($httpClient, $response):
    - This is a GET handler (browser redirect from relay page), NOT an AJAX endpoint
    - Extract 'code' and 'state' from query string of $response->request->uri
    - If error parameter present: render error HTML page and return
    - If code missing: render error HTML page ("No authorization code received") and return
    - Parse state via PKCE::parseState($state) — extract nonce
    - Load and delete verifier via PKCE::loadAndDeleteVerifier($nonce)
    - If no verifier found: render error HTML page ("Authorization session expired or
      already used. Please try again from the Settings page.") and return
    - Determine client_id (same logic as _pkceStartHandler)
    - Call PKCE::exchangeCode($code, $clientId, $verifier, sub { ... })
    - In the exchange callback:
      On success ($tokenData):
        a. Use the access_token to GET /me via SimpleAsyncHTTP to get spotify user ID
           and display_name. URL: https://api.spotify.com/v1/me,
           header Authorization: Bearer $tokenData->{access_token}
        b. In the /me callback on success:
           - Extract user ID from $profile->{id} (NOT display_name — id is stable)
           - Derive accountId = substr(Digest::MD5::md5_hex($userId), 0, 8)
           - Compute expires_at = time() + ($tokenData->{expires_in} || 3600)
           - Store tokens via PKCE::storeTokens($accountId, {
               access_token => $tokenData->{access_token},
               refresh_token => $tokenData->{refresh_token},
               expires_at => $expires_at,
               client_id => $clientId,
               scope => $tokenData->{scope}
             })
           - Create/update account in prefs (same pattern as _storeAccountPrefs in
             TokenManager.pm): set accounts->{$accountId} = { displayName => $displayName,
             spotifyUserId => $userId }. Set activeAccount if none set.
           - Ensure account cache directory exists and has chmod 0700
           - Redirect browser to Settings page: send HTTP 302 with Location header
             pointing to the Settings URL (use SETTINGS_URL constant path).
             Build a simple HTML response with meta refresh as fallback.
        c. In the /me callback on error: use userId 'unknown' as fallback displayName,
           still store tokens and create account (display name updates on next token use)
      On failure ($err):
        - Render error HTML page with the error message
        - Log the error

    Sub _pkceManualHandler($httpClient, $response):
    - CSRF check via _csrfCheck
    - This handles the copy-paste fallback (edge case D from urknall #176)
    - Extract 'callback_url' from POST body (the full callback URL the user pasted)
    - Parse the URL to extract code and state query parameters
      (use URI module: my $uri = URI->new($callbackUrl); my %params = $uri->query_form)
    - If code or state missing: return JSON error
    - Perform the same token exchange logic as _pkceCallbackHandler:
      parse state, load verifier, exchange code, store account
    - Return JSON: { status => 'ok', accountId => $accountId } on success
    - Return JSON: { status => 'error', message => ... } on failure
    - Unlike the callback handler, this returns JSON (AJAX call from Settings JS),
      not an HTML redirect

    Helper sub _renderPkceResultPage($httpClient, $response, $title, $message, $isError):
    - Renders a minimal HTML page with the result message
    - If not error: includes meta refresh to Settings page after 3 seconds
    - If error: includes a link back to Settings page
    - Uses the same $response->code / Slim::Web::HTTP::addHTTPResponse pattern
      as _diagnosticBundleHandler
    - Page styling: simple centered card, consistent with relay page look

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser JS to LMS Settings | LMS web UI — protected by CSRF check on write endpoints |
| LMS to Spotify token endpoint | HTTPS POST — code_verifier proves possession |
| User-pasted URL to LMS | Untrusted input — must validate structure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-49-08 | Spoofing | CSRF on /pkce/start | medium | mitigate | _csrfCheck validates X-Requested-With header (same as existing discovery handlers) |
| T-49-09 | Spoofing | CSRF on /pkce/manual | medium | mitigate | _csrfCheck on the manual handler; _pkceCallbackHandler is exempt (browser redirect, not AJAX) |
| T-49-10 | Tampering | Malicious pasted URL in manual handler | medium | mitigate | URL is only used to extract code/state query params — no redirect, no fetch to the URL itself |
| T-49-11 | Information Disclosure | Token in template variables | high | mitigate | No token values passed to template; only pkceConfigured boolean and account metadata |
| T-49-12 | Elevation of Privilege | Account takeover via PKCE | low | mitigate | Account creation requires valid Spotify OAuth code + matching verifier; display name verified via /me API |
| T-49-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this plan — Perl and HTML only |
</threat_model>
