    Create Plugins/SpotOn/API/PKCE.pm — a stateless PKCE utility module for AUTH-01 and AUTH-02.

    Module header: package Plugins::SpotOn::API::PKCE, use strict/warnings, use Exporter for constants.

    Imports: Digest::SHA qw(sha256), MIME::Base64 qw(encode_base64url decode_base64url encode_base64),
    Crypt::OpenSSL::Random, JSON::XS::VersionOneAndTwo, URI::Escape qw(uri_escape),
    File::Spec::Functions qw(catdir catfile), Slim::Utils::Cache, Slim::Utils::Log, Slim::Utils::Prefs.

    Import SPOTON_DEFAULT_CLIENT_ID from Client.pm using the same require-at-runtime pattern as
    TokenManager.pm (lines 29-32) to avoid circular compile-time dependency.

    Constants (exported via Exporter @EXPORT_OK):
    - GITHUB_PAGES_REDIRECT_URI = 'https://stiefenm.github.io/spoton/auth/'
    - PKCE_SCOPES arrayref with these 13 scopes: streaming, user-read-recently-played, user-top-read,
      user-library-read, user-library-modify, user-follow-read, user-read-playback-state,
      user-modify-playback-state, user-read-currently-playing, user-read-playback-position,
      playlist-read-private, playlist-modify-public, playlist-modify-private
    - PKCE_VERIFIER_TTL = 600 (10 minutes — generous for auth flow completion)
    - PKCE_TOKEN_FILE = 'pkce_tokens.json'

    Package-level: $log via logger('plugin.spoton'), $prefs via preferences('plugin.spoton'),
    $cache via Slim::Utils::Cache->new('spoton', Plugins::SpotOn::Plugin::SPOTON_CACHE_VERSION()).

    Sub generateCodeVerifier(): Use Crypt::OpenSSL::Random::random_bytes(64), encode with
    encode_base64url(), strip trailing '=' padding, return result (86 chars, within 43-128 range).
    The verifier must use only unreserved URI characters per RFC 7636 section 4.1.

    Sub generateCodeChallenge($verifier): Compute sha256($verifier) (raw bytes), encode with
    encode_base64url(), strip trailing '=' padding, return the S256 challenge string.

    Sub buildState($callbackUrl, $nonce): Create a hashref { callback_url => $callbackUrl,
    nonce => $nonce }, JSON-encode it, base64url-encode the JSON string, strip '=' padding,
    return the encoded state. The callback_url is the LMS-local URL
    (e.g., http://lms:9000/plugins/SpotOn/settings/pkce/callback).

    Sub parseState($stateStr): base64url-decode, JSON-decode, return the hashref.
    Return undef on any parse failure (eval-guarded). Log a warning on failure.

    Sub buildAuthorizationUrl($clientId, $codeChallenge, $stateStr): Build the full Spotify
    authorization URL. Base URL: https://accounts.spotify.com/authorize. Query parameters:
    client_id, response_type=code, redirect_uri=GITHUB_PAGES_REDIRECT_URI (uri_escape'd),
    scope (join PKCE_SCOPES with space, uri_escape'd), code_challenge_method=S256,
    code_challenge, state. Return the URL string.

    Sub exchangeCode($code, $clientId, $codeVerifier, $cb): Use SimpleAsyncHTTP to POST to
    https://accounts.spotify.com/api/token with Content-Type application/x-www-form-urlencoded.
    Body parameters: grant_type=authorization_code, code=$code,
    redirect_uri=GITHUB_PAGES_REDIRECT_URI, client_id=$clientId, code_verifier=$codeVerifier.
    On 200: JSON-decode response body, call $cb->($tokenData) where $tokenData has
    access_token, refresh_token, expires_in, scope, token_type.
    On error: log error, call $cb->(undef, $errorMsg).
    No client_secret — PKCE replaces it.

    Sub refreshAccessToken($refreshToken, $clientId, $cb): Same SimpleAsyncHTTP POST pattern.
    Body: grant_type=refresh_token, refresh_token=$refreshToken, client_id=$clientId.
    On 200: JSON-decode, call $cb->($tokenData). The response includes a NEW refresh_token
    (rotation) — caller must persist it atomically.
    On error: log error, call $cb->(undef, $errorMsg).

    Sub storeTokens($accountId, $tokenData): Atomic write-then-rename pattern from spike findings.
    Compute target path: catfile(_accountDir($accountId), PKCE_TOKEN_FILE).
    Create the account directory if it does not exist (File::Path::make_path).
    Write JSON to a temp file "$target.tmp.$$", chmod 0600 on temp file,
    rename temp to target. Log success. Return 1 on success, 0 on failure.
    The $tokenData hashref should include: access_token, refresh_token, expires_at
    (computed as time() + expires_in), client_id, scope.

    Sub loadTokens($accountId): Read catfile(_accountDir($accountId), PKCE_TOKEN_FILE).
    Return the parsed hashref or undef if file missing or parse fails.

    Sub storeVerifier($nonce, $verifier): Store in cache with key "spoton_pkce_verifier_$nonce"
    and TTL of PKCE_VERIFIER_TTL. This bridges the HTTP request boundary between
    /pkce/start and /pkce/callback.

    Sub loadAndDeleteVerifier($nonce): Get from cache key "spoton_pkce_verifier_$nonce",
    immediately remove the key (one-time use — prevents replay), return the verifier string
    or undef.

    Private sub _accountDir($accountId): Return catdir(preferences('server')->get('cachedir'),
    'spoton', $accountId). Same directory structure as TokenManager.pm uses.

    Security: Never log access_token or refresh_token values. Log only accountId (masked
    to first 4 chars + "****"), client_id (masked to first 8 chars + "..."), and TTL/scope.

    End with 1; as required for Perl modules.

    https://stiefenm.github.io/spoton/auth/. This is the OAuth redirect_uri registered
    in the Spotify Developer App. Per AUTH-01.

    This page receives the Spotify OAuth callback (after user authorizes) and redirects
    the browser to the user's LMS instance. The LMS callback URL is encoded in the
    OAuth state parameter.

    HTML structure: minimal, no external dependencies (no CSS frameworks, no JS libraries).
    Single self-contained HTML file with inline CSS and JS.

    Page title: "SpotOn — Spotify Authorization"

    Visual design: centered card on light background. SpotOn branding text (no logo image).
    Status message area. Fallback code display area.

    JavaScript logic (inline, runs on DOMContentLoaded):

    1. Parse URL query parameters: extract 'code', 'state', 'error', 'error_description'.

    2. If 'error' parameter present: display error message to user (e.g., "Authorization
       was denied" or the error_description). Stop processing.

    3. If 'code' is missing: display "Invalid callback — no authorization code received." Stop.

    4. Decode state parameter: base64url-decode, JSON.parse. Extract callback_url and nonce.
       Use atob() after replacing URL-safe chars (- to +, _ to /) and adding padding.

    5. Validate callback_url (edge case C — RFC1918/loopback/.local restriction):
       Parse the callback_url hostname. Allow ONLY:
       - IPv4 RFC1918: 10.x.x.x, 172.16-31.x.x, 192.168.x.x
       - IPv4 loopback: 127.x.x.x
       - IPv6 loopback: ::1, [::1]
       - .local hostnames (mDNS)
       - localhost
       If validation fails: display "Security error: callback target is not a local address."
       and show the full callback URL for manual inspection. Stop.

    6. Build redirect URL: append ?code=CODE&state=STATE to the callback_url (properly
       URL-encoding the values).

    7. Display TWO things simultaneously (edge case D — copy-paste fallback):
       a. A "Redirecting to your LMS server..." message with the full redirect URL visible
       b. A clearly labeled section: "If you are not redirected automatically, copy this
          URL and open it in a browser that can reach your LMS server:"
          followed by the full redirect URL in a read-only input field with a "Copy" button.

    8. After a 1-second delay, attempt redirect via window.location.href = redirectUrl
       (edge case B — uses navigation, not fetch, so CORS is not an issue).

    9. After 5 seconds, if still on this page, update status to "Redirect did not complete.
       Please use the URL above to complete authorization manually."

    Security constraints per edge case A: The page must NOT contain or reference the
    code_verifier. The verifier stays exclusively in the LMS Settings handler. This page
    only forwards the authorization code and state parameter.

    The page should work without JavaScript disabled (show a message asking to enable JS).
    Use noscript tag for this.

    Add a meta viewport tag for mobile responsiveness (users may authorize on phone).

    No analytics, no tracking, no external requests. Pure static relay.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to GitHub Pages relay | Untrusted — attacker could intercept OAuth callback |
| GitHub Pages relay to LMS | Untrusted — relay redirects to user-controlled URL in state param |
| LMS to Spotify API | Standard HTTPS with OAuth tokens |
| Disk storage (pkce_tokens.json) | Local filesystem — needs chmod 0600 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-49-01 | Spoofing | OAuth callback interception | low | mitigate | PKCE S256 makes intercepted code useless without code_verifier (which never leaves LMS) |
| T-49-02 | Tampering | State parameter modification | medium | mitigate | Nonce validation in callback handler; RFC1918/loopback/.local check on redirect target |
| T-49-03 | Information Disclosure | Token logging | high | mitigate | PKCE.pm never logs access_token or refresh_token values; only masked accountId and client_id |
| T-49-04 | Information Disclosure | Token file permissions | medium | mitigate | pkce_tokens.json written with chmod 0600; account directory chmod 0700 |
| T-49-05 | Repudiation | Verifier replay | medium | mitigate | loadAndDeleteVerifier removes cache entry after first use; 10-minute TTL auto-expires |
| T-49-06 | Denial of Service | Repeated auth starts | low | accept | Each start only generates a verifier and URL — minimal resource cost |
| T-49-07 | Tampering | Open redirect via state | high | mitigate | Relay page validates callback_url hostname is RFC1918/loopback/.local only |
| T-49-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this plan — pure Perl + static HTML |
</threat_model>
