## Review finding: non-uniform call sites

Two of the 17 `unless ($data)` call sites have non-standard fallback semantics and must NOT be mechanically substituted:

1. **Album-track pagination (~Plugin.pm:2441):** Inside a `$fetchPage` closure, on error the code first falls back to any accumulated tracks (`if (!@items) { push ... }`). The _authRequiredItem substitution applies ONLY to the inner `if (!@items)` push, NOT the outer `unless` block — the partial-result fallback must be preserved.

2. **WebPlayer/Made-For-You fallback (~Plugin.pm:2725):** The error source may be sp_dc/Pathfinder, not PKCE. The _authRequiredItem helper still works correctly here (it checks accountNeedsMigration/needsReauth state, not the error source), but the executor must verify this site's existing graceful-degradation behavior is preserved.

## Review finding: hint scope asymmetry (deliberate)

The OPML migration hint in handleFeed checks only the active account via `accountNeedsMigration(_getAccountId($client))`. The Settings banner checks all accounts via `anyAccountNeedsMigration()`. This is deliberate: OPML Browse/Library always operates on the active account, so a per-account check is correct. Settings is a global configuration page where migration state of ANY account is relevant.
