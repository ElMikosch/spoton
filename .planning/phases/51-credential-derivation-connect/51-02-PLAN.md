## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN guest → librespot ZeroConf discovery | untrusted guest credentials enter the daemon session |
| daemon stderr → Perl crash classifier | daemon-controlled text drives repair decisions |
| credentials.json on disk | deletion/re-creation controlled by crash handler |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-51-01 | Spoofing / Tampering | ZeroConf guest overwrites primary credentials.json | high | mitigate | Already mitigated at the Rust layer (reconnect_cache without credentials_location — unified.rs "Phase 14"); Task 3 verifies presence and documents; no Perl rebuild (D-09) |
| T-51-07 | Tampering | stderr text spoofing triggers spurious credential repair | low | accept | stderr is written only by the spoton child process we spawned; worst case is one extra derivation cycle, bounded by D-05 cooldown |
| T-51-08 | DoS | crash-loop of delete→derive→restart hammering Spotify | medium | mitigate | D-05 cooldown inside Credentials.pm gates every re-derive; generic crash-loop protection (_checkStartTimes) still applies to daemon restarts (Task 3) |
| T-51-09 | Elevation of Privilege | mismatch repair deleting the wrong account's data | medium | mitigate | Mismatch repair unlinks only the account-scoped credentials.json resolved via credentialsPathFor; never directory trees, never the flat legacy dir (Task 2) |

No package-manager installs in this phase — no supply-chain row required.
