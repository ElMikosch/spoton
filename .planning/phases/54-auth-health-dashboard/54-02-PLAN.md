<objective>
Wire the backend state from Plan 01 into a per-account Auth Health Dashboard section on the Settings page (D-01, D-02, D-03).

Five indicators per account:
1. PKCE Status — token present, refresh valid, last API call time
2. sp_dc Cookie Status — empty/valid/expired/secrets_down enum
3. Connect Status — daemon alive, PID, uptime
4. Migration Status — credentials.json without pkce_tokens.json
5. Audio-Key Cohort — ok/denied/throttled (passive, per D-02)

All reads are passive cache/prefs/accessor queries. Zero outbound HTTP/API calls triggered by page render (D-02 extended to all indicators).

Purpose: Users can see at a glance whether each account's auth chain is healthy, which accounts need migration, and whether the audio-key cohort issue affects them.

Output: Settings.pm gains _collectAuthHealth aggregation; basic.html gains a collapsible dashboard section; strings.txt gains dashboard i18n keys.
</objective>
