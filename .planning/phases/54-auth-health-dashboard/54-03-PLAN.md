    2. SpotOn's $qty >= 500 heuristic is structurally unreachable from any play command path.
    3. When SpotOn's coderef is invoked for a play command, $args->{quantity} is undef,
       defaulting to 200 via the || 200 fallback.

    Ask user to test on their dev/test LMS machine:
    - From the Playlists list, use "Play now" on a playlist row, check DIAG log for quantity
    - Drill into a playlist, use "Play All Songs" from track context menu, check DIAG log
    - Same two tests for Liked Songs and Albums

    Expected outcome: Play commands show quantity=undef, confirming the >= 500 threshold is unreachable.

    After confirming, present three fix options:

    Option A — Lower/replace the quantity heuristic:
    Pros: Minimal code change, keeps existing architecture.
    Cons: Hard to find a reliable alternative signal; any new threshold is equally arbitrary.

    Option B — Add explicit Play All child menu item:
    Pros: SpotOn controls the trigger end-to-end via passthrough flag; reliable regardless of
    LMS client UI; additive.
    Cons: Adds a menu item; changes UX slightly.

    Option C — Accept current behavior (matches Spotty-NG):
    Pros: Zero code change; Spotty-NG has the same limitation.
    Cons: Folder-level Play now on large playlists plays first ~200 tracks only.

    Record the user's choice in the SUMMARY for Plan 04 to read.
