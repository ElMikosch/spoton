<objective>
Fix CR-02 / Gap 2: WebPlayer._requestToken over-attributes STATE_EXPIRED to transient failures.

Purpose: Currently, a network timeout, 5xx error, or malformed JSON response during token mint
writes STATE_EXPIRED to the cache -- identical to a genuine 400/401 cookie rejection. This
misleads Settings/OPML/Status into showing "sp_dc expired -- re-enter it" after ordinary
transient failures, directly contradicting the D-03/D-04/D-05 cause-distinct degradation
design. The fix scopes _setState(STATE_EXPIRED) to only the 400/401 branch and adds
regression tests covering the exact code path (WR-04). Per D-04.

Output: Corrected WebPlayer.pm error handling + t/21_webplayer_mint_errors.t regression tests
</objective>
