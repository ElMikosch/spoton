<objective>
Strip the dual-flavor system (own/bundled) from Client.pm per D-04. Remove
_resolveStartFlavor, _lookupBundledHint, _rememberBundledHint, _is404Deprecated,
@KNOWN_DEPRECATED_FAMILIES, BUNDLED_HINT_TTL, BUNDLED_HINT_KEY_PREFIX, and the
bundled-fallback retry branch from _doFlavouredRequest's error callback. Simplify the
getToken call site from 3-arg to 2-arg. Collapse per-flavor rate-limit cache keys to a
single key.

Fix Status.pm _collectTokens to remove the isDiscoveryRunning call that would crash at
runtime after Plan 01 deletes that method (H-1). Update status.html to render the
consolidated rate-limit status and remove the Discovery Running row (H-1). Fix
t/13_status_page.t key assertions to match the new single rateLimited key (H-2).

Purpose: D-04 completion -- the flavor system was a Keymaster-specific workaround that
PKCE tokens do not need (Spike 002: 21/21 endpoints work with single client_id).
Status subsystem updated to match (H-1, H-2).

Output: Simplified Client.pm, fixed Status.pm + status.html, updated test suites.
</objective>
